# 台本を書く

このファイルは **manual 経路（Claude Code）と api 経路（script:generate）の両方が使う**。
TypeScript の文字列に埋めない。二重管理になった時点で経路の切替は不可能になる。

`script:prepare` が、このファイルの内容にネタ・一次ソース・直近20件を足した
`.work/<id>/prompt.md` を書き出す。人間はそれを読み、api 経路は同じものを送る。

**台本を手で直したら、その修正方針をこのファイルに反映する。**
manual フェーズは無料期間ではなく**プロンプト開発期間**。気づきを頭に留めると
api 切替時に全部失われる。

---

## 出力

`content/scripts/<id>.json` に台本 JSON を書く。スキーマは `src/schema/script.ts`。
**スキーマを緩めて通すのは禁止。** 通らないなら台本の側を直す。

検証:

```bash
npm run script:verify -- --topic <id>
```

error が消えるまで直す。warn は理由が言えるなら残してよい。

## 事実の扱い

- **数値・日付・バージョン・製品名は一次ソースからだけ取る。生成しない。**
- 取った値は `facts` に入れ、`sources[].excerpt` に根拠を残す
- 一次ソースに無いことは書かない。「たぶんこう」は動画に載せない
- `sourceDate` は情報の日付。`publishedAt` は投稿日。**表示するのは前者**

## リテンション設計（ここが成否の大半）

lint（`scripts/lint-script.ts`）で機械的に落ちる。書く前に知っておくと手戻りがない。

### hook

- **24文字以内**
- **音声なしで意味が通ること。** 初回視聴の多くは無音か音が出遅れる。
  フレーム0から全画面テキストで出る
- 指示語（これ / それ / この / その / こう / そう …）を入れない。
  ナレーションに依存した瞬間、無音の1枚として成立しなくなる
- `hookStyle` は id のハッシュから決まる（question / number / negation）。
  `.work/<id>/prompt.md` に出ているので、その型に合う文にする。
  台本では省略してよい（書くなら導出値と一致していること）
  - `question`: 疑問形。末尾の「？」はテンプレ側が付けるので文には書かない
  - `number`: **数字で始める**（「3倍」「47%」）。先頭の数値が巨大表示になる
  - `negation`: 否定・逆張り。打ち消し線が入る

### オープンループ

- `payoffSection` は**最終セクション**を指す
- 最終セクションの `narration` か `heading` に **hook と同じ語**を入れる。
  同じ言葉で閉じないと「回収された」と認識されない

### 尺と密度

- 実測の尺が **65〜75秒**（完了率優先。60秒はCreator Rewardsの下限）
- **視覚変化の間隔は2秒以下。** 字幕チャンク1つが2秒を超えると落ちる
- セクションは3〜5本。1本あたり10〜18秒

**ナレーションは全体で 380〜430文字・1セクション 85〜100文字**
（VOICEVOX / 青山龍星・ノーマル・`speedScale: 1.05` の実測。
正味 7.1文字/秒 + チャンクごとに前後 0.2秒の無音 = 実効 6.0文字/秒）。

> **文字数からの推定は1割ずれる。** 漢字の多さでモーラ数が変わるため、
> 文字数は尺の代理指標にならない（「所要は約2分です」8文字 と
> 「同じ台本から書き出せます」12文字 がほぼ同じ尺になる）。
>
> だから**合わせ方はこう**:
>
> 1. だいたいの文字数で書く
> 2. `npm run synthesize -- --topic <id>` を回す（数秒。キャッシュに当たる）
> 3. 範囲外なら「約N文字 足す/削る」と実測から出るので、そのとおり直す
> 4. 2 に戻る
>
> レンダーは尺が決まってから1回でよい。話者や `speedScale` を変えたときも
> この手順で取り直す（上の数値は書き換える）。

### ナレーションと字幕

`narration` の `|` が**字幕の割れ方**。TTS へは除去して渡す。

- **尺を決めるのは文字数ではなくモーラ数（読みの長さ）。**
  「週3本を続けられます」は10文字だが読みは14モーラ（シューサンボンヲツヅケラレマス）で
  1.8秒。漢字が多い句は文字数が少なくても長い
- 目安: **1チャンク 12モーラ以下**（約 `0.11秒/モーラ + 0.2秒`）。
  **セクションの最後のチャンクは10モーラ以下**（末尾余白 0.3秒 と合算されるため）
- 文字数でいえば 8〜10文字、末尾は6〜7文字。漢字が続く句はさらに短く
- 意味の切れ目で割る。「Claude|Code」のような固有名詞の分断をしない
- **読みをそのまま書く。** TTS は書いてあるとおりに読む。
  `React` → 「リアクト」、`MP4` → 「エムピーフォー」、`UI` → 「ユーアイ」。
  英字の綴りは telop / visual 側に置く（画面では英字、音声ではカナ）
- 改行を入れない。割るのは `|` だけ

`|` の位置を動かしても**音声は再生成されない**（キャッシュのキーはチャンクの文面）。
だから字幕の割れ方は後からいくらでも調整できる。
逆に**ナレーションの文面を変えると音声代と待ち時間が積む。**
**原稿を先に確定し、演出は後。**

### telop（字幕とは別物）

- 字幕 = ナレーションそのもの（生成物）。telop = デザイン要素（入力）
- `atSec` はセクション先頭からの相対秒。セクションの尺を超えると落ちる
- セクションの尺は音声長で決まるので、**冒頭寄り（0〜8秒）に置く**のが安全
- 1セクション2つまで。増やすと画面が喧しくなる

### 鮮度

| shelfLife | 日付 | 使いどころ |
|---|---|---|
| `hot` | 大きく焼き込む | 鮮度が価値そのもの。情報が7日以内 |
| `evergreen` | 出さない（バージョンのみ） | 3ヶ月後も読める解説。ロングテール |

配分は **hot 1本 + evergreen 2本**。

## 重複

`(entity, version, angle)` の3つ組で判定する。完全一致は **reject**。

- `Next.js 16.1` → `16.2` は別ネタ（連続性が出て良い）
- 同じ `16.2` の「キャッシュ」と「ルーティング」は別ネタ
- 同じ `16.2` の「キャッシュ」を二度は**重複**

`.work/<id>/prompt.md` に直近20件が入っている。
**3つ組が違っても実質同じ話なら避ける**（そこはコードでは判定しない）。

## 書き終わったら

1. `npm run script:verify -- --topic <id>` を通す
2. `npm run today` を回す（音声合成 → 3媒体レンダー → 投稿前ゲート）
3. `npm run still -- --topic <id> --at 1.5` を**音を想像せずに**見る
